## ✅ 她已拍板(2026-07-21)

1. **载体 = 双形态**:(a) **"抬眼可见"的常驻形态** — 她的核心诉求是不需要"想起来才打开",打开电脑/看手机就能看到今日牌(参考 iPhone 主屏小组件)。技术事实:真正的桌面/主屏小组件必须原生 app;最快的准常驻形态 = **浏览器新标签页插件**(每开新标签自动展示)或 Mac 菜单栏小组件。(b) **网页版必须有** — 作品集访客从 case study 页跳转进来就能玩。实施顺序:网页版 → Chrome 新标签插件/Mac 菜单栏(她自用)→ iOS WidgetKit(上架)。
2. **牌阵 = 一简一详,克制**(她看了爱占心的一堆牌阵后明确"不要乱七八糟"):**单张**(日签 + 问事,同一机制)+ **一个详细勘察牌阵**(三张,推荐"情境/障碍/建议";时间之流可 v1.5)。五张/马蹄/十字等一律 v2 以后。
3. **逆位 = 要做**(她原话:抽的时候正反打乱,"都是正位感觉没那么专业")。实现:牌面无逆位专用画(抽到逆位 = 牌面旋转 180° 展示,行业通行);解读用"**光面/影面**"语言 — 逆位是这张牌能量的受阻/内收/过度面,**依然温柔**,禁止恐吓式逆位断言。§3 规则相应生效:每张牌准备正/逆两组含义词。

另:她的作品集 case study 页 ≠ 产品本体 — case study 讲过程、放牌面、展示怎么做的,末尾链接到网页版产品。

## 0. 产品锚(一切决定的依据)

塔罗不是预言固定的未来,而是探索无意识的自我。做**每日的情绪陪伴**:轻轻问一件事,抽一张牌,得到一段温柔、具体、带行动提示的解读。气质 = 温暖治愈 + 一点神圣神秘(= 牌面的气质延伸到整个 app)。

## 1. 载体(需要她拍板 ①)

- **方案 A(推荐)**:手机优先的 Web App,做在现有 repo 新路由(如 `/garden`),用现有 Next.js 栈和部署管线,一两周能出可用版;支持"添加到主屏幕"后像原生 app 一样全屏打开。先用真解读验证产品,之后要上 App Store 再用壳(Capacitor)打包,界面代码不用重写。
- 方案 B:直接原生 iOS(SwiftUI)。上架正规,但要开发者账号($99/年)、审核周期、整套新技术栈,牌面风格还原成本高,验证周期慢一个数量级。
- 建议:A → 验证解读质量和留存 → 再考虑包壳上架。

## 2. 牌阵方案(需要她拍板 ②:v1 放哪几个)

| 牌阵 | 抽几张 | 回答什么 | 建议 |
|---|---|---|---|
| 每日一张(日签) | 1 | 今天的基调/提醒,不用提问 | **v1 核心**,打开 app 的默认仪式 |
| 单张问事 | 1 | 一个具体的小困扰 | **v1** |
| 三张 · 过去/现在/未来 | 3 | 一件事的来龙去脉 | **v1** |
| 三张 · 情境/障碍/建议 | 3 | 具体处境怎么办 | v1 二选一(和上面选一个先做) |
| 是/否倾向 | 1 | 轻量决策倾向(只给"倾向+理由",不给断言) | v1.5 |
| 凯尔特十字等大阵 | 10 | 深度全景 | v2,先不做 |

建议 v1 = **日签 + 单张问事 + 一个三张阵**,克制,把解读质量做到最好。

## 3. AI 解读语言规则(她点名要的文档核心)

### 3.1 语气
- 像一位懂心理学、说话温柔的朋友;第二人称"你";中文;不堆玄学术语,神秘感来自意象而不是黑话。
- 温柔但**具体**——永远落到她问的那件事上,不写万金油。

### 3.2 固定结构(每次解读四段,总长 150–260 字)
1. **映照**:这张牌的画面此刻映出你问题里的什么(必须点到用户的问题)。
2. **看见**:牌想让你看见的一件事(核心洞察,一件、不贪多)。
3. **小行动**:今天就能做的一个具体小动作(可执行、低门槛)。
4. **收尾**:一句轻的祝语/陪伴语(≤20 字)。

三张阵 = 每张两三句(映照+看见),最后合起来给一段"小行动+收尾"。

### 3.3 意象纪律(防 AI 胡编,最重要的一条)
解读里提到的画面细节,**必须真的在那张牌面上**。牌面意象表从 `app/lab/tarot/page.tsx` 的 22 个场景 + 4 花色 + 4 宫廷气质生成(如愚人=沙丘边缘/小小的人/一朵白花/发光的未知;死神=一片落瓣/水面下发光的新芽)。实现时把 78 张的意象关键词表作为 prompt 素材随牌注入。

### 3.4 禁止
- 预言生死、疾病、官司、怀孕、投资输赢等重大结果;
- 绝对化断言("一定""必然""注定");恐吓、制造焦虑、宿命论;
- 医疗/法律/金融专业建议(引导去找专业人士);
- 评判和说教("你就是太……")。逆位:**v1 不做逆位**(牌面没有设计逆位语义),用"这张牌的光面/影面"在文案里自然表达两义(需要她拍板 ③)。

### 3.5 安全底线
用户输入出现自伤/伤人/危机信号 → 不解牌,输出固定的温柔转介模板(陪伴语 + 建议联系信任的人/专业热线)。

### 3.6 技术形态
Claude API(建议 claude-sonnet-5,快且稳),系统 prompt = 本规则 + 该牌意象表 + 牌阵位置含义;温度低一点保稳定;每次解读缓存,同一天日签不重抽不重写。

## 4. App 除卡牌外的样子(界面地图,5 屏)

1. **今日** — 打开即见:问候一句 + 今日牌位(未抽=牌背呼吸微光,点击翻牌);抽过则显示今天的牌和解读入口。
2. **提问抽牌** — 输入"想问的一件事"(一行,可跳过)→ 选牌阵(日签外的两种)→ 抽牌动画(牌背扇形展开,拖动选牌,翻转 + 尘光)。
3. **解读页** — 牌面大图(就是 SVG 组件,不是位图)+ 四段解读 + "存进手记"。
4. **手记** — 时间轴:日期 + 牌缩略 + 当时的问题 + 可补写两句感受(这是"情绪陪伴"的复利,回看很治愈)。
5. **牌库** — 78 张图鉴,逐张看画面故事(大牌 22 幕已有中文一句话,可扩)。

视觉 = 牌面语言的延伸:paper 米色底、mist/teal、gold 点缀、serif 标题(Cormorant 系)、月光 halo、无脸插画;动效轻而有含义(呼吸、翻牌、尘光升起),不做炫技滚动。数据 v1 存本机(localStorage,无账号无登录),v2 再谈同步。
